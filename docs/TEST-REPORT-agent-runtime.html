Findings that change the design

#FindingWhat I did
1Sandbox cannot reach the internet on this Daytona tier. Probe from inside a sandbox: npm registry reachable (200); Modal, example.com and modal.com all blocked (connection reset). This matches Daytona's tier rules, which cannot be overridden per sandbox.Switched the design: the agent runs in the sandbox but the Modal call is made from our side. The sandbox builds the prompt and runs tools, we call Modal, the sandbox cleans the answer. This also means no Modal credential ever enters the sandbox (better than the shortcut we discussed). The earlier "sandbox dials home to a Hub / LLM gateway" design (PRD §5.2, §5.10) only works if the Daytona organisation is upgraded to a tier with full egress.
2No tunnel needed. We reach the agent through Daytona's own preview URL for port 8080, protected by a per-sandbox secret plus Daytona's preview token.Removed Cloudflare tunnel from the test.
3First run, the agent invented a price ("bike fitting is $75") that was not in its knowledge.Added an explicit "only state facts from the knowledge, otherwise say you will check with the team" rule. Re-run: for Brompton bikes and bike fittings the agent now says it will check. Still needs a worker-side check for invented numbers; prompt rules are not a guarantee.
4Atlas refuses connections from this machine (TLS alert 80, IP 205.175.106.12). The Atlas network access list does not include it.Ran the message tests on an in-memory Mongo using the same schema validators. The updated message validators have not been applied to Atlas. Add the IP (or 0.0.0.0/0 for the hackathon) in Atlas, then run pnpm db:setup in web/.
5Model returns its reasoning in a separate reasoning_content field and puts leading blank lines in content.The agent only forwards content, trimmed. Reasoning is dropped, never sent to a customer.
6Processes die when a sandbox stops (as the PRD assumed). The wake path restarts the agent and waits for it.Wake took 3.0 s including the LLM call, under the 5 s target.
7Your Daytona account already contains one stopped sandbox with agentOffice labels that is not from this project.Left untouched. My test sandboxes carry the label app=sales-agent and are deleted at the end of each run.

What was not tested

  • Real iMessage in or out. The test used a loopback channel so no real person was messaged. The Worker is written against a ChannelAdapter; the Spectrum adapter is not written yet.
  • Voice calls. Only a voice-style text turn through the same agent. The SIP gateway, speech-to-text and text-to-speech are not built. Photon's SIP path is documented but unverified end to end.
  • Atlas. Blocked by the network access list (finding 4).
  • Prod-shape pieces: custom baseline snapshot, warm pool, token rotation, nightly reconciler, auth on the web app, the Next.js Deploy button. Code for the Hub and LLM gateway exists (agent/src/platform.ts) but is not exercised here because of finding 1.
  • Load, concurrency, and long-running soak.
