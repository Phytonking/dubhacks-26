Voice latency: ground parameters for the whole route

Your phone → Photon → ElevenLabs → the agent on Daytona → back to your ear. How slow each piece is, how fast each must be, and the rules that keep the total under control.

See also AGENT-CORE.html: call logging is now live, and customer identification and the T-Mobile prompt are defined there.

Review 2026-10-18: The budget lines B and E (Daytona proxy hops) apply only if the engine moves into the sandbox. In v1 the engine runs on the host, so ElevenLabs calls the host directly; deploy it near the model and Atlas. Decision D-A1 needs your sign-off (C1, C9). See AGENT-MASTER.html.

1. Summary

Verdict: the route can hit about 1.0 s median, under 2 s at the 95th percentile from "caller stops talking" to "caller hears the first word", with the agent running inside the Daytona sandbox. Two measurements made this feasible, and one caveat decides whether we get there.
  • The model is fast if we turn reasoning off. First word in 138 ms with reasoning_effort: "none", versus 318 ms at low (what the text agent uses today). The endpoint's default is the slowest setting.
  • Daytona's proxy streams and is cheap. About 100 ms round trip to a sandbox, server-sent events arrive as they are produced (not buffered), and a signed URL works with no special headers, so ElevenLabs can call the sandbox directly.
  • Sandboxes can now reach the internet. My earlier test said they could not. Today Modal answered from inside a sandbox in 0.2 s. That removes the need to relay model calls through our laptop-hosted platform.
  • Caveat: about 40 percent of the budget (listening and speaking) belongs to ElevenLabs, and I have only estimates for it. A real measured call is the first gate (§10).

The big idea in one line: the "hot path" is only ElevenLabs → agent in sandbox → model → back. Nothing else (database writes, our servers, logging, fact extraction) is allowed to sit on it.

2. The route

  1. Photon carries the call to ElevenLabs over SIP (configured) and emits call events to our worker.
  2. ElevenLabs transcribes the caller, decides when they finished, and later turns the reply into speech.
  3. The agent (agentd, a small web service inside the business's Daytona sandbox) receives the conversation over HTTPS, builds the prompt from its in-memory copy of the business and caller context, and streams the model's reply back.
  4. The model is Modal's Qwen endpoint.
  5. Everything else is off the hot path (§5 rule 1).

New fact that helps: Photon tells us who is calling, early

I watched your test calls arrive in the live event stream: call.started → call.ringing → call.answered (0.7 s later) → call.connected → call.ended. Photon's event schema includes caller.handle (E.164) and callee. So the platform learns who is calling and which business at call.started, before the caller says anything, and independently of whether ElevenLabs passes caller ID. That resolves the biggest unknown in the voice PRD and gives us time to wake and prepare the sandbox.

What we control directly (B–E): about 365 ms median. That part is evidence-based. The two ElevenLabs hops (A and F, 625 ms) are the largest and least certain, so the first real test call is the gate.

For comparison: the text pipeline today

The existing text path (sandbox /turn → host model call → sandbox /finalize) was reported at 1.2 s for a full round trip and 880 ms for a voice-style turn, with the model at effort low and two extra sandbox round trips. Reusing it for voice would blow the budget before ElevenLabs's share is even counted. Hence a dedicated voice path.

5. Ground rules (the parameters)

#RuleWhy
1The hot path contains only: ElevenLabs → agentd → model → ElevenLabs. No database call, no call to our own servers, no logging service, no fact extraction between the caller's sentence and the first spoken wordEvery extra hop costs 50–150 ms and adds a way to fail
2Everything the agent needs is already in the sandbox's memory when the first utterance arrives: business rules, knowledge, and the caller's profile, summary and recent messages. The platform worker pushes it ("prime") at call.startedMongo is fast (12 ms) but it lives behind our servers; the sandbox doesn't hold database credentials, and we don't want it to
3Model settings for voice: reasoning_effort: "none", stream: true, max_tokens: 100, temperature 0.3. The text agent keeps low138 ms vs 318 ms to first word. Needs a quality check on guardrail cases (§9)
4Replies are short: at most 2 sentences or about 35 words, spoken style, numbers written out. The first complete sentence is flushed to ElevenLabs immediately; the rest followsTTS can start before the reply ends; shorter replies also feel more natural on a phone
5Writes are off the hot path. The agent queues turn records, facts and tool audits in memory; the platform drains them after the call (and the post-call webhook is the authoritative transcript)No database write may delay a spoken word
6Tools on the hot path must finish in under 150 ms and run in the sandbox against memory (knowledge search, remembering a fact, ending the call). Anything slower (booking, sending a text) is started asynchronously, with a spoken filler: "One moment..."Keeps tool use from adding seconds of silence
7Guardrails run per sentence, locally (pattern checks under 1 ms), before a sentence is released to ElevenLabs. A blocked sentence is replaced by a safe lineStreaming makes whole-message checks impossible; the cost is negligible
8Keep connections warm: agentd holds a reusable HTTPS connection to the model endpoint (the first request costs 100+ ms more for the TLS handshake); the platform keeps its connection to the sandbox warmFirst request over a new connection measured 308 ms vs about 100 ms warm
9The sandbox is running before the caller can speak (§6)A cold start (about 3 s) is the single worst latency event
10Timeouts: model first token within 1.5 s; whole turn within 4 s; if exceeded, speak a fallback line and continue (§8)A bounded worst case beats an open-ended silence
11Interruptions cancel work immediately. When ElevenLabs closes the stream (caller talked over the agent), agentd aborts the model requestSaves tokens and avoids stale replies
12Co-locate. Sandbox region, model endpoint and Atlas should be in the same US region as ElevenLabs's servers where we have a choice. Verify where each runsCross-region adds 30–80 ms per hop
13Every hop is timestamped and one latency record is stored per turn (§9)We can't improve what we don't measure

6. Cold start: the worst case

Sandboxes auto-stop after 15 idle minutes to save money. A stopped sandbox takes about 3 s to wake. The caller's first question can arrive only after the greeting plays, which gives us a window to hide the wake, but a thin one:

t = 0.0 s  call.started       (Photon event: caller number + business known)
t = 0.0 s  platform wakes the sandbox if stopped, then primes it   ← starts here, not at the first question
t = 0.7 s  call.answered      (observed)
t = 0.7 s  ElevenLabs plays the fixed greeting (about 2–3 s of speech)
t = 3–4 s  caller's first utterance ends; ElevenLabs sends the first request
           wake (about 3 s) + prime (about 0.2 s) just fits; no margin for a slow wake
MitigationEffectCost
Pre-wake on call.startedHides most of the wake behind the greetingNone. The worker already receives these events
Keep voice-enabled businesses warm during business hours (stop auto-stop, or refresh activity)Removes the cold case for expected callersSandbox running cost (not priced here). Make it a per-business setting
A greeting of 3 s or longer that states it is an AI assistantExtra cover; also the disclosure we wantSlightly slower to the point
If still not ready at the first request: speak "One moment please" and answer when readyCaller hears something instead of dead airAwkward but safe

Wake time was last measured in the earlier test (3.0 s including the model call). It should be re-measured, along with the start-up time of agentd inside the sandbox, as part of step L1.

7. Agent on Daytona: what changes

The current agent in the sandbox (agentd.mjs) only builds prompts and cleans answers; the model call is made by our host because sandboxes used to have no internet. With the network open, the whole turn can happen in the sandbox. Required changes:

PieceChange
agentd endpointAdd POST /v1/chat/completions that speaks the OpenAI streaming format ElevenLabs expects (server-sent events, ends with [DONE])
URL ElevenLabs callsA signed Daytona preview URL for port 8080: no custom headers, proven to work today. Maximum lifetime is 24 h, so a rotation job re-issues it daily and updates the ElevenLabs agent's server URL through ElevenLabs's API (needs an ElevenLabs API key). Alternative to test later: mark the sandbox public and rely on a secret path segment
Calling the modelSee decision D1 (where the model credential lives). Either way: keep-alive connection, stream:true, effort none
ContextNew POST /prime (host → sandbox): business config, knowledge, caller profile, summary, recent messages. Cached per caller number and per ElevenLabs conversation. Updates to business config push a new version
Matching the callThe first model request carries ElevenLabs's caller ID if Photon's SIP headers provide it. If not, and exactly one primed call is active for that business, bind to it; if several are active and ambiguous, fall back to asking the caller. Photon's caller.handle makes the primed set exact
Writesagentd keeps an in-memory outbox (turn records, facts, tool audits). The platform pulls it after call.ended and via the ElevenLabs post-call webhook; nothing is written during the call
SecurityRequest must carry a secret (path segment and, if ElevenLabs supports it, a bearer). Sandbox still holds no Mongo, Photon or Daytona credentials
D1, the open design choice: where does the model credential live?
  • Gateway (safer): the sandbox calls our own LLM gateway, which holds the Modal key and clamps tokens (already designed in platform.ts). Costs one extra hop (about 20–60 ms if the gateway runs near Modal, much more behind a laptop tunnel). It must be deployed on an always-on host first.
  • Credential in the sandbox (faster): the sandbox is untrusted (customers can try to inject prompts), so a leaked key could be abused. Only acceptable with a scoped, rate-limited, revocable token. I can't confirm Modal's proxy tokens support scoping.
Recommendation: build for the gateway design, measure the extra hop, and only fall back to a scoped token if the budget demands it.

9. How we will measure

One latency record per turn, written after the call from the agent's outbox:

{ orgId, callId, turn,
  t_request_in,        // agentd received ElevenLabs's request (ms since call start)
  t_prompt_ready,      // after building the prompt            (target < 5 ms after in)
  t_model_request,     // sent to the model
  t_model_first_token, // first model token
  t_first_sentence,    // first sentence released to ElevenLabs (guardrail-checked)
  t_done, reasoning: "none", tokens_in, tokens_out, interrupted }
  • Server-side hops (B–E) come from these timestamps. The ElevenLabs share (A and F) comes from its conversation record or from timing a recorded test call. I have not verified which timing fields ElevenLabs exposes.
  • Automated probe: latency-probe.mts (exists) re-runs the measurements in §3. Add a synthetic "turn" test that posts a realistic request to the signed URL and records first-sentence time end to end.
  • Quality check for effort none: run a fixed set of 30–40 prompts (pricing, hours, out-of-knowledge questions, discount pressure, injection attempts) at low and none, compare for invented facts and guardrail slips. Only ship none if it holds up.
  • Alerts: p95 first sentence above 800 ms for the agent share; any turn above 3.5 s; wake time above 5 s.

11. Decisions needed

  1. Accept the targets? Median 1.2 s, p95 2.0 s, hard cap 3.5 s from end of caller speech to first audio. (Budget total is about 1.0 s.)
  2. D1: model credential via a gateway (safer, one more hop) or a scoped token in the sandbox (faster, riskier)? If gateway, where do we deploy it?
  3. URL type: signed URL with daily rotation (proven) or public sandbox with secret path (untested). I recommend signed first.
  4. Keep-warm policy: always warm for voice-enabled businesses during set hours? Needs a cost check on Daytona's running price.
  5. ElevenLabs: your plan tier, an API key for URL updates (stored as a platform secret, never in the sandbox), and which voice and speed settings to start with.
  6. Voice model effort: OK to use none for voice pending the quality check in §9?
