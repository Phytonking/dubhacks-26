Sales Agent Platform — Documentation

One place for everything we need during the hackathon. Add a section whenever we learn something worth keeping.

Project

Overview

A platform where a business owner runs an AI sales agent that talks to their customers. One business = one org = one agent = one Daytona sandbox. Customers reach the agent over iMessage first, then WhatsApp, then SMS and voice, all through Photon. Everything is stored in MongoDB Atlas; the owner sees it all in a Next.js console.

Setup & commands

cd web
pnpm install
# credentials: web/.env.local (gitignored) with MONGODB_URI and MONGODB_DB=salesagent
pnpm db:setup          # create collections, apply validators + indexes (idempotent, never deletes data)
pnpm db:seed           # demo business "Sunrise Bike Shop" (refuses if data exists)
pnpm db:seed -- --reset   # wipe + reseed (DESTRUCTIVE)
pnpm db:local          # optional local MongoDB on :27017 instead of Atlas
pnpm dev               # http://localhost:3000   ·   GET /api/health pings Mongo
Secrets. atlas-credentials.env and every *.env are gitignored (root .gitignore). Never commit them or paste the URI in chat/docs. The Atlas password was shared as a file; rotate it when convenient.
No auth yet. getCurrentOrg() in web/src/lib/queries.ts serves the first org in the database. Don't deploy the console to a public URL until login exists.

Design principles

  • Tenant = business = org. orgId on every tenant document (even messages), first in every tenant index, required by every query helper.
  • Channel-agnostic. Contacts have many handles; one conversation per contact spans channels; messages carry channel.
  • Mongo is the system of record. Sandboxes and harness memory are disposable.
  • Embed small bounded data, reference unbounded data. Handles, facts, guardrails, attachments embedded; messages, tool calls, chunks separate.
  • Denormalize for the inbox. lastMessageAt/Preview on conversations.
  • Constraints in the database, not just code. Unique indexes and validators catch races and bad writes from any service.

Entity relationships

Every box except orgs carries orgId. Dashed = secondary reference (knowledge_chunks → knowledge, sandboxes ↔ agent, channel_lines ↔ messages by channel). Solid arrows = "belongs to".

Inbound message write path

0. line = channel_lines.findOne({channel, address: toNumber})  -> orgId
1. contact = findOneAndUpdate({orgId, handle}, {$setOnInsert:{...}}, {upsert:true})   // race-safe: unique index
2. conversation = findOneAndUpdate({orgId, contactId}, {$setOnInsert:{mode:"agent"}}, {upsert:true})
3. messages.insertOne({... channel, channelMsgId})   // E11000 => already processed, stop (commit point)
4. conversations.updateOne({_id}, {$set:{lastMessageAt, lastMessagePreview, lastChannel}})
5. mode === "agent" ? dispatch to agent : notify owner
6. usage.updateOne({orgId, day}, {$inc:{messagesIn:1}}, {upsert:true})

No multi-document transaction needed: 1–2 are idempotent upserts, 3 is the commit point, 4 and 6 are safe to repeat.

Integrations

Photon (Spectrum)

  • SDK: spectrum-ts (MIT, TypeScript). Hosted path: Spectrum Cloud; sign up at app.photon.codes for PROJECT_ID + PROJECT_SECRET.
  • Core loop: Spectrum({projectId, projectSecret, providers:[imessage.config()]}) → for await (const [space, message] of app.messages) → space.responding(...) + message.reply(...).
  • Providers: iMessage, WhatsApp Business, Telegram, Slack, Terminal, voice (SIP), custom via definePlatform. iMessage supports typing indicators, reactions, threaded replies, groups.
  • Needs a long-lived process (persistent stream) or Photon's webhook mode, so not plain Vercel serverless.
  • Unknown: pricing, rate limits, API-driven line provisioning, multi-tenant model, voice STT/TTS owner. Ask Photon.
  • Avoid imessage-kit (Mac-bound, AppleScript, 2s polling).
  • Links: spectrum-ts · docs

Daytona

  • SDK: @daytona/sdk; env DAYTONA_API_KEY, DAYTONA_API_URL, DAYTONA_TARGET. daytona.create({...}) → sandbox.process.executeCommand(...).
  • Plan: one baseline snapshot, one sandbox per business, auto-stop when idle, state mirrored in sandboxes.
  • Pending: connectors from the team. Confirm create params (snapshot, resources, auto-stop, labels) in the Sandbox reference.
  • Links: TypeScript SDK
